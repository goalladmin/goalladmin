# 常见问题与排障

先确定访问的是平台、代理商还是商户，并记录时间、访问地址、状态码、响应中的业务 `code` 和 `requestId`。不要提交密码、完整令牌或邀请链接。HTTP 200 也可能携带非零业务错误码。

## 页面访问与登录

| 现象 | 优先检查 |
| --- | --- |
| 连接被拒绝、页面打不开 | 对应后端/前端进程是否启动，宿主机端口是否正确，容器是否健康；先查看 Compose ps 和日志 |
| 证书不受信任或域名不匹配 | 证书链、证书有效期、SAN 域名、系统时间；生产安装浏览器信任的证书，不关闭校验 |
| 域名返回 404 | 三端 Host 是否与 `GA_*_HOST` 一致，是否进了正确 nginx；未知 Host 和别的端 API 前缀被拒绝是预期行为 |
| 登录成功但刷新后退出 | 页面与 API 是否同源、HTTPS 和 Secure Cookie 是否正确、允许来源是否包含实际端口；不要混用 localhost、127.0.0.1 和不同域名 |
| 登录、刷新或退出返回 403 | 检查实际 Origin、对应端的 allowedOrigins、代理设置；自写客户端还需遵守 JSON 与 `X-GA-Client: web` 请求约定 |
| 不知道初始密码 | 没有通用默认密码；平台使用管理员创建命令的随机密码，主体使用平台开通时交付的密码 |
| 主体登录失败 | 确认端地址、主体编号、账号和主体状态；编号不是数字 ID。账号、密码、主体状态和 IP 拒绝可能使用同样的对外提示 |
| 新建平台管理员刚登录没有权限 | 未配 Redis 时命令行修改可能等待授权缓存刷新，通常最多 15 秒；稍后刷新，持续异常再查角色和服务日志 |
| 反复要求改密 | 首次登录、管理员重置或密码到期；按提示完成，而不是绕过改密路由 |
| 登录时突然要输入验证码 | 这个账号在这个来源上失败过几次，或者这个账号一分钟内的登录请求（所有来源合计）超过了上限（D-103）；输入验证码照常登录。持续出现时查登录日志里这个账号的来源 |
| 429 或“请稍后再试” | 登录/验证码/密码操作配额或密码计算并发预算；等待窗口或降低操作频率，核对日志和容量，不直接放开所有限制 |

本地启动顺序和地址见 [README](../../README.md#快速开始)。如果更改了 API 端口，也要同步 Vite 的 `GA_API_TARGET`；该变量设置在启动相应前端的终端中。

## 菜单、主体与 IP 规则

**员工看不到数据中心。** 为其角色分配当前端的数据中心查看权限。主账号默认拥有；普通员工不会因为能查看子账号就自动获得数据中心权限。

**员工看不到安全设置。** 主体 IP 黑白名单只由主账号管理，这不是菜单缓存错误。普通功能权限不能开放这组专属功能。

**找不到概览里的白名单。** 已移动至“安全设置 → IP 白名单”；同组还有“IP 黑名单”。

**数据中心人数和预期不同。** 主体端只统计本端、本主体，账号总数包含主账号；排名在缺少账号查看权限时仅展示本人。平台进程监控也不是集群汇总。

**通配输入被拒绝。** 使用完整四段，例如 `116.88.8.*`、`116.88.*.*`、`116.*.*.*`；星号只能连续位于末尾，不接受双星号。黑名单还会拒绝过宽网段和当前操作者 IP。

**白名单已添加但仍被拒绝。** 白名单不能覆盖黑名单，多层白名单要同时满足。核对页面当前 IP 是否为真正客户端出口、上层规则及其他进程的刷新状态；网络出口变化也会影响结果。逐层含义见[后台使用指南](admin-guide.md#ip-访问控制)。

**过期黑名单仍占数量。** 过期后不再生效，但仍计入每主体 1000 条存储上限；显示“包含过期”后删除不再需要的记录。达到存储上限时可续期现有规则，或先删除再新增。

**被自己配置的规则挡住。** 联系平台管理员，必要时由服务器维护者按[恢复流程](operations.md#账号与-ip-规则恢复)核对并修正具体规则。不要清空所有主体的策略来代替定位。

## 入驻与邀请

**登录页没有申请入口。** 自助入驻默认关闭，先检查相应 `/onboarding/config` 响应及容器中实际生效的开关。`.env` 修改后只 restart 不会更新容器环境变量。

**关闭入驻后已有申请还在。** 关闭控制新申请和新邀请，不撤销历史申请，也不停止已经开通的账号。平台仍可审核已有申请。

**邀请页刷新后不能继续。** 邀请凭证在首次打开后从地址栏移除，不保存在浏览器存储；重新打开原始邀请链接。链接已使用、过期或撤销时联系邀请人，不反复提交。

**申请通过却没有收到邮件。** 框架不发送邮件或短信；审核人在通过时获得一次显示的初始密码，由平台核实联系方式后交付。遗失时走管理员重置流程。

## 启动、升级与多实例

**提示需要平台迁移。** 先停止受影响服务，用目标版本平台后端执行 `migrate up`，成功后再启动主体端。操作含义和顺序见[运维指南](operations.md#升级与迁移)。

**MySQL 连接错误。** 容器内 `127.0.0.1` 指本容器，Compose 中通常通过服务名 `mysql` 连接；本地开发示例使用宿主机 3307。检查用户名、目标库、网络和授权，避免把开发或 e2e 指向生产库。

**Redis 不可用但后端仍健康。** 这是允许计数降级的设计；`readyz` 主要检查数据库。查看 Redis 连接、认证、ACL 与应用日志；共享状态恢复前，各实例本地计数可能让合计配额放宽，本地验证码需要回到生成实例。

**重建一个后端后入口仍报 502/504。** 容器 healthy 和 nginx 重新解析并接入是两个阶段。确认恢复实例已实际处理入口流量后再维护另一台；不要把 DNS 缓存时间当成恢复时限保证。详见[多实例部署](multi-instance.md)。

**改了配置没有生效。** 核对加载的配置文件、环境变量覆盖、Compose 是否将该变量传给服务、容器是否重新创建。同一端的全部副本要保持一致。

**旧版本不能识别密码。** 新版本可能已将密码改用 Argon2id 或 PBKDF2；仅替换旧二进制不能恢复兼容。升级前规划回退窗口，见[密码哈希指南](password-hash.md#从-v010-升级)。

## 验证命令的区别

| 命令 | 覆盖 |
| --- | --- |
| `make ci` | 格式、静态检查、依赖边界、门禁自测、许可证、Go 竞态测试、前端 lint/类型/单元测试/构建 |
| `make e2e` | 启动三端后端与前端，执行 Chromium 浏览器流程；需要测试数据库与 Playwright 浏览器 |
| `make vuln` | 独立的 Go 依赖公告扫描，需要可用网络；不包含在 make ci 内 |

验证失败时先保存最早的失败信息。数据库连接失败或浏览器缺失不代表业务断言已经执行；串行 e2e 的前置用例失败会让后续用例不运行。修改后完整重跑对应范围，不能用跳过用例、删除断言或重复重试代替修复。
