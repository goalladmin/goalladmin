# 后台使用指南

平台、代理商、商户有各自的登录入口。平台负责管理主体和审核入驻；代理商、商户在自己的主体范围内管理员工、角色、会话和访问规则。部署与地址配置见[三端部署指南](portals-deployment.md)。

## 登录与账号

| 账号 | 登录所需信息 | 管理范围 |
| --- | --- | --- |
| 平台超级管理员 | 平台地址、账号、密码 | 平台管理功能；由服务器命令创建 |
| 平台普通管理员 | 平台地址、账号、密码 | 分配给其角色的功能和数据范围 |
| 代理商或商户主账号 | 对应端地址、主体编号、账号、密码 | 当前主体的管理功能，包括专属安全设置 |
| 主体员工 | 对应端地址、主体编号、账号、密码 | 当前主体内获授权的功能 |

系统没有通用默认密码。平台初始管理员由部署者执行 `make admin` 或 `server admin create -username admin` 创建，命令只显示一次随机密码。主体主账号的初始密码由平台开通或审核时生成，只向执行操作的管理员显示一次。通过受控渠道交付编号、账号和密码，首次登录后按页面提示改密。

主体编号用于区分不同代理商或商户，例如平台开通后显示的 `A…` 或 `M…` 编号。它不是员工账号，也不是系统内部的数字 ID。即使账号名称相同，不同主体和不同端也不能共用登录身份。

忘记密码时：平台超级管理员由服务器管理员执行命令重置；主体主账号联系平台管理员；员工联系有相应权限的管理员。具体恢复操作见[运维指南](operations.md#账号与-ip-规则恢复)。

## 平台后台

| 菜单 | 用途 |
| --- | --- |
| 数据中心 | 查看用户、登录、操作统计及趋势 |
| 安全监控 | 查看安全事件摘要、当前进程的运行与数据库指标 |
| 工作台 | 查看本人的活动、设备和快捷入口 |
| 代理商管理、商户管理 | 开通主体、查看账号、调整状态和商户归属、重置主账号密码 |
| 入驻申请 | 核实申请，执行通过或驳回 |
| 运维中心 | 查询操作、登录、错误和安全事件，使用调查时间线，管理会话 |
| 权限管理 | 用户、角色、部门、岗位及菜单显示设置 |
| 系统设置 | 字典、只读安全策略、IP 访问控制 |
| 个人中心 | 本人资料、头像、密码及其他设备会话 |

普通管理员只能看到已授权的功能。平台安全策略页展示当前生效值，密码和登录策略由部署配置调整；菜单管理只改变显示名、图标、排序、分组和隐藏状态，不改变后端权限。

### 开通主体

1. 在代理商列表或商户列表中执行开通，填写名称、联系信息和主账号名。
2. 商户可以直属平台，也可以选择所属代理商。
3. 保存后记下主体编号和一次显示的初始密码，交付给主账号使用者。
4. 主账号在相应端首次登录并改密，再建立员工角色和子账号。

停用主体会影响该主体所有账号的后续访问。调整商户归属会改变代理商的可见范围，但不会把代理商账号变成商户账号。

## 代理商与商户后台

主账号默认进入菜单首位的“数据中心”。数据中心只统计当前端、当前主体；有“查看子账号”权限时可查看本主体的活跃账号排名，否则排名只包含本人。员工需要单独获得数据中心查看权限，没有时按其可见菜单进入首个页面。

“概览”展示主体资料和有权查看的计数；账号总数包含主账号和子账号。“账号与权限”管理子账号、角色与权限、在线会话；“日志”展示当前主体的登录和操作记录。代理商另有只读“名下商户”和主账号的“商户邀请”。

两端都有“安全设置”菜单组，下设“IP 白名单”和“IP 黑名单”。这组菜单只属于主账号，给员工授予全部普通权限也不会开放。白名单已从概览移至这里。

### 员工与角色

1. 主账号先在“角色与权限”新建角色，按职责勾选功能权限。
2. 在“子账号”新建员工，分配角色，并按页面提示交付密码。
3. 员工首次登录改密后，只看到已授权菜单和按钮。
4. 通过“在线会话”下线不再需要的会话；通过停用账号终止后续使用。

标记为敏感的权限由主账号授予。员工不能修改或停用主账号、替主账号分配角色或下线其会话。主体内不能重置主账号密码；主账号自己改密，忘记时由平台处理。隐藏按钮不是访问控制的依据，服务端仍会检查每次请求。

## 入驻与邀请

自助入驻默认关闭，由部署者通过配置启用，后台没有随意开启它的开关。平台仍可直接开通主体。

| 配置 | 控制内容 |
| --- | --- |
| `GA_ONBOARDING_AGENT_ENABLED` | 代理商自助申请入口和提交 |
| `GA_ONBOARDING_MERCHANT_ENABLED` | 商户自助申请及代理商创建商户邀请 |
| `GA_ONBOARDING_MERCHANT_ORIGIN` | 商户邀请链接的前端来源；开启商户入驻时必填，release 模式必须为 HTTPS |

开启后，申请人在对应登录页进入申请，填写主体名称、联系人、电话、主账号名和验证码，保存提交后给出的申请编号。提交本身不会开通账号；平台在“入驻申请”核实联系信息后通过或驳回。通过才创建主体和主账号，初始密码只向审核人显示一次。框架不自动发送邮件或短信，也不提供匿名进度查询入口。

代理商主账号可以创建商户邀请链接，有效期 7 天，最多提交一份申请。未使用的邀请可以撤销。通过邀请提交的商户申请关联该代理商；无邀请的商户申请直属平台。链接打开后邀请凭证会从地址栏移除，刷新申请页时需重新打开原链接。

关闭代理商申请不单独关闭商户邀请。关闭商户申请会同时停止新商户申请和新邀请创建；旧表单也无法继续提交。已有申请仍可审核，已有邀请仍可查看、撤销，已开通账号继续可用。修改容器环境变量后需要重建相应容器，见[部署中的开关更新](portals-deployment.md#自助入驻)。

## IP 访问控制

IP 规则匹配服务器识别到的来源地址。经过代理或 CDN 时，先让部署者核对真实来源 IP；页面中的“当前 IP”若显示代理地址，不应直接将其当作用户网络设置规则。

### 可以怎样输入

| 输入示例 | 含义 | 保存后的写法 |
| --- | --- | --- |
| `116.88.8.9` | 单个 IPv4 地址 | `116.88.8.9/32` |
| `116.88.8.*` | 最后一段任意 | `116.88.8.0/24` |
| `116.88.*.*` | 后两段任意 | `116.88.0.0/16` |
| `116.*.*.*` | 后三段任意 | `116.0.0.0/8` |
| `2001:db8::1` | 单个 IPv6 地址 | `2001:db8::1/128` |
| `2001:db8::/64` | IPv6 网段 | `2001:db8::/64` |

也可以直接填 CIDR。星号必须占满一段，并连续放在 IPv4 地址尾部；不接受 `116.*.8.*`、双星号或 IPv6 星号。保存后显示等价 CIDR 是正常的，不需要自己计算掩码。上表只演示格式，应换成实际需要的地址范围。

### 白名单

白名单为空表示这一层不限制；非空时只允许名单内的来源。每份最多 100 条，点击保存会整份替换。保存前可以用“添加当前 IP”保留自己的访问路径，系统也会拒绝会立即把当前操作者挡在外面的设置。公网出口变化后仍可能需要调整规则。

平台可以设置端、主体和账号白名单；主体主账号管理当前主体的白名单。多层白名单同时存在时，必须同时满足，不是任选一层通过。清空主体白名单不会清除上层规则。

### 黑名单

平台的全局黑名单作用于三端；主体主账号的黑名单只作用于本主体。黑名单命中时优先拒绝，不能用白名单覆盖。检查顺序为全局黑名单、端白名单、主体黑名单，再检查主体与账号白名单；健康检查不受全局 IP 门禁影响。

新增黑名单时填写地址、有效期和备注；对同一网段再次保存会更新有效期及备注。可以选择永久，或最多一年的有效期。每主体最多 100 条生效黑名单、含过期记录最多 1000 条；平台的全局黑名单最多 10000 条生效，两者各自计数。主体的黑名单把该进来的人挡在外面时（例如更换主账号之后），平台可以在代理商、商户的详情里查看这份名单并整体清空，需要“主账号管理”权限。过期项不再拦截，但仍计入存储条数，勾选“包含过期”后可删除。

不能封禁当前操作者的地址，也不能提交宽于 IPv4 `/8` 或 IPv6 `/16` 的黑名单。解除规则后，其他实例会通过通知或定期刷新跟进；数据库异常时可能暂时继续使用旧规则，不能假设所有进程同一瞬间更新。

## 会话、日志与个人设置

个人中心可以修改资料、头像和密码，或下线其他设备而保留当前会话。锁屏在服务端生效；刷新浏览器不会解除锁定。退出登录后再离开共享设备。

排查操作时，记录发生时间、端、主体编号和页面给出的请求 ID，由有权限的人查询相应日志。密码、完整令牌和邀请链接不应作为工单正文。数据库审计记录没有网页删除入口；历史会话清理和日志留存由部署者维护，见[运维指南](operations.md)。
